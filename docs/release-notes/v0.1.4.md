# PlainEssay v0.1.4

修复 macOS 上窗口置前（已激活）时无法拖动的问题。

## 根因

这是 Tauri 在 macOS 上的原生层行为，不是页面事件没触发。相关 issue：
[tauri-apps/tauri#15623](https://github.com/tauri-apps/tauri/issues/15623)。

`titleBarStyle: "Overlay"` 使用 full-size content view，`WKWebView` 覆盖了整个窗口（包括标题栏区域）。窗口未激活时，第一次点击会被 `WKWebView` 的 `acceptsFirstMouse` 拒绝，落到原生窗口上，于是能激活并拖动；窗口已激活时，点击直接进入 `WKWebView`，`performWindowDragWithEvent` 不会启动原生拖动，所以“激活后拖不动”。v0.1.3 的 `data-tauri-drag-region="deep"` 只能让 JS 识别到点击区域，无法绕开这个原生层限制。

## 修复

- 不再使用 `Overlay`，改为 `titleBarStyle: "Transparent"` + `hiddenTitle`：保留原生 macOS 标题栏和红绿灯，但网页内容不再覆盖标题栏；拖窗口由系统原生标题栏处理，窗口是否激活都能拖动。
- 设置窗口背景色 `#fcfcfa`，让透明标题栏与纸张色调一致。
- 移除页面自定义拖动区域和 `5.25rem` 红绿灯左内边距；内容从原生标题栏下方开始。
- 移除 Tauri 相关拖动 CSS 与 `tauri-macos` 标记。按钮、输入框、正文交互不受影响。

这是 Tauri 原生修复（tao/wry）落地前的平台规避方案。视觉上比 Overlay 多一条原生标题栏，但拖动行为与普通 macOS 窗口一致，不再依赖页面的 `mousedown` 转发。

## 功能

包含 v0.1.2 / v0.1.3 的全部编辑能力：

- Undo / Redo、查找替换（`⌘F`）
- 本地图片粘贴/拖放、Markdown 图片导出、Word 内嵌图片
- 选中字数、空状态新文案
- 本地 SQLite 存储，无账号、无云同步、无遥测

## 安装

1. 下载 `PlainEssay_0.1.4_universal.dmg`（Apple Silicon + Intel，macOS 12+）。
2. 打开 DMG，将 PlainEssay 拖入 `/Applications`。
3. 右键应用 → 打开 → 打开。未签名/未公证，首次启动需要手动放行。
4. 若提示已损坏，执行：

```sh
xattr -dr com.apple.quarantine /Applications/PlainEssay.app
```

## 数据位置

```text
~/Library/Application Support/com.phanstal.plainessay/plainessay.db
```

删除应用不会删除数据；如需清空，请手动删除上述目录。

## 已知限制

- 无代码签名与公证，无自动更新
- 仅段落 + 粗体/斜体/下划线 + 本地图片；不支持标题层级、列表、链接、图片缩放/裁切
- 单张图片上限 12 MB；WebP 可显示和导出 Markdown，但 Word 导出会跳过
- 查找替换按单个文本节点匹配，跨格式边界的短语不视为一个匹配
- 删除不可撤销
- 窗口关闭时最多丢失最后约 600 ms 的输入（返回或 `⌘S` 会立即保存）
- 无数据库加密、无同步、仅英文界面
- macOS 标题栏样式由 Overlay 改为原生透明标题栏，这是 Tauri #15623 的规避方案
